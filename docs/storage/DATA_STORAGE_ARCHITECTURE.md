# Data Storage Architecture

GOAL-06C.5 adds a local research storage contract. GOAL-STORAGE-01 hardens that
contract as an infrastructure-only gate. It is not a production database, not a
broker integration, and not a source of recommendation output.

## Local Root

Future heavy data writes must resolve the runtime data root from
`ASHARE_PREMARKET_DATA_ROOT`. The documented fallback is
`~/data/ashare_premarket/`; under GOAL-STORAGE-01 that fallback is
documentation-only and is not a production deployment assumption.

The data root must remain outside this Git repository. GitHub stores only code,
configs, schemas, tiny samples, manifest summaries, coverage summaries, audit
reports, readiness reports, and workflow docs.

## Local Directory Contract

```text
raw/
  akshare/
  eastmoney/
  cninfo/
  sina/
bundles/
  engineering_pilot/<bundle_id>/
lake/
  ohlcv_daily/
  benchmark_daily/
  announcements_metadata/
  source_coverage/
  pit_signal_panel/
  label_panel/
  stage6c_engineering_panel/
metadata/
  ashare_premarket.duckdb
  schema_registry/
exports/
  github_artifacts/
audit_samples/
```

Parquet and DuckDB are allowed only in the local data root. If those runtimes
are unavailable, CSV may be used with the same logical schemas.

`exports/audit_samples/` is retained only as a legacy alias for previously
documented sample paths. The canonical STORAGE-01 sample boundary is
`audit_samples/`, and committed samples require a later explicit approval.

## Future Placement Rules

- Provider raw data: `raw/<provider>/<category>/<bundle_id>/`; manifest and
  SHA-256 checksums required; full payload commits forbidden.
- Source-backed bundles: `bundles/<bundle_tier>/<bundle_id>/`; immutable bundle
  IDs and no in-place overwrites.
- PIT signal panels: `lake/pit_signal_panel/<schema_version>/<bundle_id>/`.
- Label panels: `lake/label_panel/<schema_version>/<bundle_id>/`.
- Stage 6C engineering panels:
  `lake/stage6c_engineering_panel/<schema_version>/<bundle_id>/`.
- GOAL-07B risk overlay diagnostics:
  `lake/goal07b_risk_overlay_diagnostics/<schema_version>/<bundle_id>/`; no new
  risk rows are generated by STORAGE-01.
- Future GOAL-08B review diagnostics:
  `lake/goal08b_review_diagnostics/<schema_version>/<bundle_id>/`; locked until
  a separate explicit review-only prototype request.
- Future GOAL-09 position-band diagnostics:
  `lake/goal09_position_band_diagnostics/<schema_version>/<bundle_id>/`; locked
  until a separate explicit diagnostics request.
- Future backtest outputs:
  `lake/backtest_diagnostics/<schema_version>/<bundle_id>/`; locked until a
  separate explicit future backtest goal.
- Future dashboard/daily report exports:
  `exports/daily_reports/<schema_version>/<bundle_id>/`; locked until a
  separate explicit export goal.

## Versioning, Manifests, And Checksums

Bundle IDs are immutable and use the pattern
`<goal_or_stage>_<purpose>_<as_of_date>_<source_hash>_vNN`. A bundle manifest
must include bundle ID, tier, schema version, creation/as-of dates, source
commit SHA, workflow status version, universe/calendar/provider versions, local
paths, row counts, source coverage, schema registry references, quality flags,
non-actionable flags, downstream lock flags, and a checksum manifest.

Every raw payload, curated table, manifest, and checksum manifest uses SHA-256.
Checksum manifests live under `metadata/checksums/<bundle_id>.json`.

Schemas are governed by `configs/storage/table_schema_registry.yaml`; local
mirrors may live under `metadata/schema_registry/`. Ad hoc columns are forbidden
unless a future explicit schema migration updates the registry.

## GitHub Hygiene

Forbidden committed artifacts include raw provider payloads, raw HTML, full
announcement text, database files, Parquet lake files, notebooks, caches, logs,
private credentials, large model artifacts, production model files, array/model
binaries, and local lake bundles.

The storage gate is:

```bash
python scripts/audit_storage_policy.py
```

The bundle summary gates are:

```bash
python scripts/build_data_bundle_manifest.py
python scripts/audit_data_bundle_manifest.py
```

The GOAL-STORAGE-01 hardening gates are:

```bash
python scripts/run_goal_storage01_local_research_lake_hardening_gate.py
python scripts/audit_goal_storage01_local_research_lake_hardening_gate.py
```

STORAGE-01 does not fetch data, create local lake files, generate
recommendation or position diagnostics, run backtests, create dashboards, write
production data, activate factor mining, or unlock GOAL-08B.
